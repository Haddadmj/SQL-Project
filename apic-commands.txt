================================================================================
APIC TOOLKIT COMMANDS - PRODUCT / APPLICATION SUBSCRIPTION LISTING
================================================================================
Run these by hand, in order, from a terminal where `apic` is on PATH.
Replace <PLACEHOLDERS> as you go - each step tells you where its value came from.

Variables used below:
  SERVER = apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa
  USER   = malhaddad
  ORG    = <PROVIDER_ORG>     (from step 3)
  CATALOG= <CATALOG>          (from step 4)

Notes:
  * SERVER is a bare hostname - no https:// prefix.
  * Add `--format json --output -` to any list command to get JSON on stdout
    instead of a formatted table. Useful for piping into jq.
  * Add `--live` / `--scope catalog` where shown; the defaults differ per command.


--------------------------------------------------------------------------------
STEP 1 - FIND THE REALM (do this first; wrong realm = login failure)
--------------------------------------------------------------------------------
apic identity-providers:list --scope provider --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa

  Output lists the provider realms. You want the one backed by the local user
  registry - usually:
      provider/default-idp-2    local user registry (api-manager-lur)
      provider/default-idp-1    OIDC / common services
  Use the exact realm name from this output in step 2.


--------------------------------------------------------------------------------
STEP 2 - LOGIN
--------------------------------------------------------------------------------
apic login --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --username malhaddad --realm provider/default-idp-2

  Omitting --password makes the toolkit prompt for it (keeps it out of your
  shell history). To pass it inline instead:

apic login --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --username malhaddad --password "<PASSWORD>" --realm provider/default-idp-2

  Verify the session:

apic --version
apic orgs:list --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --my


--------------------------------------------------------------------------------
STEP 3 - LIST PROVIDER ORGS  -> gives you ORG
--------------------------------------------------------------------------------
apic orgs:list --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --my

  Take the `name` column. That is <PROVIDER_ORG> for every command below.


--------------------------------------------------------------------------------
STEP 4 - LIST CATALOGS  -> gives you CATALOG
--------------------------------------------------------------------------------
apic catalogs:list --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG>

  Take the `name` column (e.g. sandbox). That is <CATALOG> below.


--------------------------------------------------------------------------------
STEP 5 - LIST PRODUCTS IN THE CATALOG
--------------------------------------------------------------------------------
apic products:list-all --scope catalog --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG>

  Published products only:

apic products:list-all --scope catalog --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG> --format json --output - > products.json

  Each entry has name, version, title, state and url. Keep the `url` values -
  subscriptions reference products by URL, not by name.


--------------------------------------------------------------------------------
STEP 6 - LIST CONSUMER ORGS IN THE CATALOG
--------------------------------------------------------------------------------
apic consumer-orgs:list --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG>

  Take each `name`. You need one per <CONSUMER_ORG> in step 7.


--------------------------------------------------------------------------------
STEP 7 - LIST APPS IN EACH CONSUMER ORG  (repeat per consumer org)
--------------------------------------------------------------------------------
apic apps:list --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG> --consumer-org <CONSUMER_ORG>

  Take each `name`. You need one per <APP> in step 8.


--------------------------------------------------------------------------------
STEP 8 - LIST SUBSCRIPTIONS  (repeat per consumer org + app)
--------------------------------------------------------------------------------
The DEFAULT table output does NOT show which product was subscribed to - it only
shows the subscription id, plan and state. You must ask for the product field.

8a. Ask for the product fields explicitly:

apic subscriptions:list --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG> --consumer-org <CONSUMER_ORG> --app <APP> --fields id,plan,state,product_url

8b. If --fields is rejected or product_url comes back empty, take the full JSON
    record instead - the product reference is always in there somewhere:

apic subscriptions:list --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG> --consumer-org <CONSUMER_ORG> --app <APP> --format json --output -

    Depending on toolkit version the field is named product_url, product, or
    product_ref. Look at one record first to see which you have.

8c. Fallback - fetch a single subscription in full detail by its id:

apic subscriptions:get --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG> --consumer-org <CONSUMER_ORG> --app <APP> --format json --output - <SUBSCRIPTION_ID>


--------------------------------------------------------------------------------
STEP 8d - TURN THE PRODUCT URL INTO A PRODUCT NAME
--------------------------------------------------------------------------------
A product_url looks like:
  https://<SERVER>/api/catalogs/<catalog-id>/products/9f3c1e5a-....

There is no "which products is this app subscribed to" command - you have to
join it yourself. Two ways:

  (i) Match against step 5. The products.json from step 5 has both `url` and
      `name`/`title`/`version`. Look up the subscription's product_url in that
      list. This is the fast way - one product list, no extra calls.

 (ii) Resolve the id directly (the last path segment of product_url):

apic products:get --scope catalog --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa --org <PROVIDER_ORG> --catalog <CATALOG> --id <PRODUCT_ID> --fields name,title,version

This is the slow part overall: one subscriptions call per app. See the loop
scripts at the bottom to do the whole join in one pass.


--------------------------------------------------------------------------------
STEP 9 - LOGOUT
--------------------------------------------------------------------------------
apic logout --server apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa


================================================================================
OPTIONAL - LOOP OVER EVERYTHING IN ONE PASS
================================================================================

Both loops below build the product-URL -> product-name lookup from step 5 first,
then print APP -> PRODUCT lines. That join is the whole point - without it you
only get opaque URLs.

--- BASH / ZSH (macOS, Linux, Git Bash) - requires jq ------------------------
SERVER=apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa
ORG=<PROVIDER_ORG>
CATALOG=<CATALOG>

# 1. Product lookup: url -> "title (name:version)"
apic products:list-all --scope catalog --server $SERVER --org $ORG --catalog $CATALOG --format json --output - > products.json

# 2. Walk consumer orgs -> apps -> subscriptions, resolving each product_url
for CO in $(apic consumer-orgs:list --server $SERVER --org $ORG --catalog $CATALOG --format json --output - | jq -r '.results[].name'); do
  for APP in $(apic apps:list --server $SERVER --org $ORG --catalog $CATALOG --consumer-org $CO --format json --output - | jq -r '.results[].name'); do
    echo "=== $CO / $APP ==="
    apic subscriptions:list --server $SERVER --org $ORG --catalog $CATALOG --consumer-org $CO --app $APP --format json --output - \
      | jq -r --slurpfile prods products.json '
          ($prods[0].results
            | map({ key: (.url // ""), value: ((.title // .name) + " (" + (.name // "?") + ":" + (.version // "?") + ")") })
            | from_entries) as $lookup
          | .results[]
          | ($lookup[.product_url // ""] // (.product_url // "<no product on record>")) as $product
          | "  - " + $product + "   [plan: " + (.plan // "?") + ", state: " + (.state // "?") + "]"'
  done
done

  Produces:
    === finance-corg / billing-app ===
      - Accounts API (accounts-api:1.0.0)   [plan: default-plan, state: enabled]


--- POWERSHELL --------------------------------------------------------------
$SERVER  = "apic-nonpr-35f19ae6-api-manager-cp4i-nonprod.apps.nt-non-cp4i.neotek.sa"
$ORG     = "<PROVIDER_ORG>"
$CATALOG = "<CATALOG>"

# 1. Product lookup: url -> "title (name:version)"
$products = (apic products:list-all --scope catalog --server $SERVER --org $ORG --catalog $CATALOG --format json --output - | ConvertFrom-Json).results
$lookup = @{}
foreach ($p in $products) {
  if ($p.url) {
    $title = if ($p.title) { $p.title } else { $p.name }
    $lookup[$p.url] = "$title ($($p.name):$($p.version))"
  }
}

# 2. Walk consumer orgs -> apps -> subscriptions, resolving each product_url
$cos = (apic consumer-orgs:list --server $SERVER --org $ORG --catalog $CATALOG --format json --output - | ConvertFrom-Json).results
foreach ($co in $cos) {
  $apps = (apic apps:list --server $SERVER --org $ORG --catalog $CATALOG --consumer-org $co.name --format json --output - | ConvertFrom-Json).results
  foreach ($app in $apps) {
    Write-Host "=== $($co.name) / $($app.name) ==="
    $subs = (apic subscriptions:list --server $SERVER --org $ORG --catalog $CATALOG --consumer-org $co.name --app $app.name --format json --output - | ConvertFrom-Json).results
    foreach ($s in $subs) {
      $product = if ($s.product_url -and $lookup.ContainsKey($s.product_url)) {
                   $lookup[$s.product_url]
                 } elseif ($s.product_url) { $s.product_url }
                 else { "<no product on record>" }
      Write-Host "  - $product   [plan: $($s.plan), state: $($s.state)]"
    }
  }
}


================================================================================
TROUBLESHOOTING
================================================================================
"Unable to find realm"          -> re-run step 1, use the exact realm string.
"invalid_grant"                 -> username/password wrong for that realm.
"self signed certificate"       -> export NODE_TLS_REJECT_UNAUTHORIZED=0
                                   (PowerShell: $env:NODE_TLS_REJECT_UNAUTHORIZED=0)
                                   Development/non-prod only.
"Not authorized"                -> the user lacks a role in that org/catalog.
"apic: command not found"       -> toolkit not on PATH; download it from
                                   API Manager > Download Toolkit.
Flags rejected                  -> the toolkit version matters. Check the real
                                   signature with:  apic <command> --help
                                   e.g.  apic subscriptions:list --help
